# Deployment on Laravel Forge (single 1–2 GB VPS)

Sized for a low-traffic graduation demo: one server running Nginx, PHP-FPM, MySQL, Redis, Horizon (2 workers), Reverb and headless Chrome (PDF export).

## 1. Server

| Item | Value |
|---|---|
| PHP | 8.2 or newer (`composer.json` requires `^8.2`; developed on 8.2.12). Needs `redis`, `pcntl`, `posix` extensions (Forge installs them). |
| Node | 22 LTS (developed on v22.13). Needed at deploy time to build assets and by Browsershot at runtime. |
| Database | MySQL 8 (Forge default). The old `.env.example` said `pgsql`; that was wrong for this project. |
| Redis | Installed by Forge. Used for the queue, Horizon and the cache. |
| Server type | App server with MySQL + Redis. Ubuntu 22.04 or 24.04. |

### Swap (do this first on a 1 GB server)

Chrome, Horizon workers, MySQL and the `vite build` can together exhaust 1 GB.

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
sudo sysctl vm.swappiness=10
```

If `npm run build` is still killed, run it with `NODE_OPTIONS=--max-old-space-size=768`, or build locally and deploy the `public/build` folder.

### Chromium libraries and fonts (PDF export)

`npm ci` downloads Puppeteer's Chrome into `~/.cache/puppeteer` of the `forge` user. Chrome needs these system libraries:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates fonts-liberation xdg-utils \
  libatk1.0-0 libatk-bridge2.0-0 libcups2 libdrm2 libgbm1 libgtk-3-0 \
  libnspr4 libnss3 libx11-xcb1 libxcomposite1 libxdamage1 libxfixes3 \
  libxkbcommon0 libxrandr2 libpango-1.0-0 libcairo2
# Ubuntu 22.04:  sudo apt-get install -y libasound2
# Ubuntu 24.04:  sudo apt-get install -y libasound2t64
```

Arabic text in the PDF uses the **bundled** Noto Naskh Arabic font (`resources/fonts/`, SIL OFL licence, inlined by `DocumentPdfRenderer::fontCss()`), so no Arabic font package is needed. Latin text uses system fonts (`fonts-liberation` above).

**Chrome sandbox:** on Ubuntu 24.04 (and any host that blocks unprivileged user namespaces) Chrome fails to start with the sandbox on. If PDF export shows "PDF engine failed to start", set `BROWSERSHOT_NO_SANDBOX=true`. This is acceptable here because JavaScript is disabled in the render and the HTML is generated by this app.

## 2. Site setup

1. Create the site, connect the repository, enable **Quick Deploy** if wanted.
2. Create the database (Forge database tab) and put the credentials in the environment.
3. Paste `.env.example` into the Forge environment editor, then set:
   - `APP_URL`, `APP_ENV=production`, `APP_DEBUG=false`.
   - `APP_KEY`: generate **once** (Forge does this on first deploy, or `php artisan key:generate`). **Never regenerate it**: AI provider API keys stored in the database are encrypted with it and would become unreadable.
   - `DB_*`, `REDIS_*` (Forge Redis has no password by default: leave `null`).
   - `REVERB_*` and `VITE_REVERB_*` (see section 4). `VITE_*` values are baked into the JavaScript at build time, so the environment must be final **before** the deploy that runs `npm run build`.
   - `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` for the first admin (section 5).
4. Enable HTTPS (Let's Encrypt).
5. Uploads: set `client_max_body_size 25M;` in the site's Nginx config, and PHP `upload_max_filesize` / `post_max_size` to at least 25M (Forge → server → PHP). `DOCUMENT_MAX_UPLOAD_KB` defaults to 20480 (20 MB).

Uploaded files go to the **private** `local` disk (`storage/app/private/documents`). No `storage:link` is required. `storage/` and `bootstrap/cache/` must be writable by `forge` (Forge sets this up).

## 3. Deploy script

Forge → Site → Deployments:

```bash
cd $FORGE_SITE_PATH
git pull origin $FORGE_SITE_BRANCH

$FORGE_COMPOSER install --no-dev --no-interaction --prefer-dist --optimize-autoloader

npm ci
npm run build

( flock -w 10 9 || exit 1
    echo 'Restarting FPM...'; sudo -S service $FORGE_PHP_FPM reload ) 9>/tmp/fpmlock

$FORGE_PHP artisan migrate --force

$FORGE_PHP artisan config:cache
$FORGE_PHP artisan route:cache
$FORGE_PHP artisan view:cache

# Workers hold the old code in memory: ask them to exit; the Forge daemons restart them.
$FORGE_PHP artisan horizon:terminate
$FORGE_PHP artisan reverb:restart
```

`npm ci` installs dev dependencies too, on purpose: `tsc` and Vite are needed for the build. Do not add `--omit=dev` or `--ignore-scripts` (Puppeteer downloads Chrome in its install script).

First deploy only (after the first successful deploy):

```bash
php artisan db:seed --force
```

## 4. Daemons

### Horizon (queue worker; replaces `queue:listen`)

Forge → Site → Application → **Queue → Horizon** can enable it, or add a daemon manually:

| Field | Value |
|---|---|
| Command | `php8.3 artisan horizon` (use your PHP version) |
| Directory | the site root |
| User | `forge` |
| Processes | 1 |

Configuration is in `config/horizon.php`: one supervisor, `HORIZON_MAX_PROCESSES=2`, worker `timeout=200` (above the 180 s job timeout, below `retry_after`), `tries=2`, memory 128 MB per worker, workers recycled after 100 jobs or one hour. `REDIS_QUEUE_RETRY_AFTER=240` must stay above 200.

`horizon:terminate` in the deploy script makes the daemon restart onto the new code. The dashboard is at `/horizon` and is restricted to users with `role = admin` (`App\Providers\HorizonServiceProvider`).

### Reverb (websockets)

Use Forge's Reverb integration if your Forge plan offers it (Application → Reverb). It creates the daemon, the Nginx proxy and the `REVERB_*` variables. Otherwise do it by hand:

1. Daemon: `php8.3 artisan reverb:start --host=0.0.0.0 --port=8080`, directory = site root, user `forge`.
2. Nginx (Forge → Site → Edit Nginx configuration), inside the `server` block, so that the browser connects over `wss://your-domain` on port 443:

```nginx
location /app {
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Scheme $scheme;
    proxy_set_header SERVER_PORT $server_port;
    proxy_set_header REMOTE_ADDR $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
    proxy_pass http://127.0.0.1:8080;
}
location /apps {
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_pass http://127.0.0.1:8080;
}
```

3. Environment (public values used by both the PHP server and the browser build):

```
BROADCAST_CONNECTION=reverb
REVERB_HOST=your-domain.com
REVERB_PORT=443
REVERB_SCHEME=https
REVERB_SERVER_HOST=0.0.0.0
REVERB_SERVER_PORT=8080
REVERB_ALLOWED_ORIGINS=your-domain.com
VITE_REVERB_HOST="${REVERB_HOST}"   # and VITE_REVERB_PORT / _SCHEME / _APP_KEY the same way
```

Generate `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET` (any random strings; `php artisan reverb:install` can do it) before the first build.

Realtime events now carry only identifiers and status (`ProcessingResultReady`). The page re-fetches the result content over HTTP, so the 10 KB Reverb message limit is no longer a problem.

## 5. Production safety

- `APP_ENV=production`, `APP_DEBUG=false`.
- `php artisan db:seed` creates the `admin@example.com` / `student@example.com` demo accounts (password `password`) **only outside production**. In production it creates one admin from `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` if both are set (an existing account is promoted; its password is not touched). Remove the two variables afterwards.
- AI provider keys: either set `GOOGLE_AI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` before seeding, or enter them in Admin → AI Routing (stored encrypted with `APP_KEY`). Then choose the **active model** there.
- Sessions stay on the `database` driver (they survive a Redis restart); cache is on Redis.

## 6. Scheduler

`routes/console.php` schedules `horizon:snapshot` (every 5 minutes, for the Horizon metrics graphs) and `queue:prune-failed --hours=168` (daily). Enable it: Forge → Site → **Scheduler** → `php8.3 artisan schedule:run`, every minute. Nothing else depends on it; the app works without it, only the Horizon metrics are empty.

## 7. Local development notes

- Horizon needs `pcntl`/`posix` and does not run on Windows. Local Windows development keeps using `queue:listen` (`run-dev.bat`, `composer dev`). On Windows install packages with
  `composer install --ignore-platform-req=ext-pcntl --ignore-platform-req=ext-posix`.
- Local `.env` can keep `APP_ENV=local`, `REDIS_CLIENT=predis`, `REVERB_HOST=localhost`, `REVERB_PORT=6001`, `REVERB_SCHEME=http`.

## 8. Smoke test after the first deploy

1. Log in as the seeded admin, open `/horizon` (status "Active"), then Admin → AI Routing: add or check keys and pick the active model.
2. Upload a small PDF as a student: status should move to *processing*, and the tabs fill in without a page reload.
3. Export a PDF with Arabic content and open it: Arabic text must be shaped and readable.
4. `tail -f storage/logs/laravel.log` during these steps.
